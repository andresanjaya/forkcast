# Produk kemasan dan barcode (MVP 7)

Forkcast membaca EAN-13, EAN-8, UPC-A, dan UPC-E dengan [ZXing Browser](https://github.com/zxing-js/browser). Kamera diminta hanya sesudah tombol **Buka kamera barcode** ditekan. Kode dapat diketik jika kamera atau izin tidak tersedia. Kode dinormalisasi dan digit pemeriksanya divalidasi sebelum lookup.

Lookup satu produk dilakukan dari route server ke [Open Food Facts API v3](https://openfoodfacts.github.io/documentation/docs/Product-Opener/v3/products/get-api-v3-product-code/). Server hanya mengirim kode, memakai `User-Agent` Forkcast, membatasi permintaan dalam memori, memberi batas waktu 6,5 detik, dan menolak respons lebih dari 256 KB. Tidak ada foto makanan, profil, atau data log yang dikirim ke penyedia. Open Food Facts menyebut batas baca produk 15 permintaan/menit per IP dan meminta `User-Agent` khusus dalam [panduan API](https://openfoodfacts.github.io/documentation/docs/Product-Opener/api/); pembatas Forkcast 10/menit per instance dibuat lebih rendah, tetapi instance serverless tidak berbagi penghitung. Tidak ada kunci API. Data Open Food Facts tersedia dengan lisensi [ODbL dan Database Contents License](https://openfoodfacts.github.io/documentation/docs/Product-Opener/api/); aplikasi menampilkan nama dan tautan sumber dan tidak mengimpor katalog atau gambar secara massal. Halaman syarat pakai terpisah penyedia tidak dapat diakses dari lingkungan pemeriksaan ini.

Nilai `_100g` dari penyedia dipakai hanya ketika unit produk teridentifikasi sebagai g atau ml. Dokumentasi [skema produk](https://openfoodfacts.github.io/documentation/docs/Product-Opener/schemas/schemas/product/) menjelaskan bahwa `_100g` berarti per 100 g atau 100 ml untuk cairan. Nilai `_serving` dipakai jika dasar sumbernya per sajian. Jika unit atau nilai tidak cukup jelas, hasil ditandai tidak lengkap; tanpa dasar yang jelas produk tidak bisa langsung ditambahkan. Form label manual mengosongkan nilai gizi agar angka dari penyedia tidak keliru diberi status "diisi pengguna". Ukuran kemasan hanya ditampilkan; tidak diasumsikan sebagai satu sajian. Nilai gizi kosong tetap `null`, termasuk dalam ringkasan harian dan mingguan.

Migration `20261012000200_packaged_food.sql` menambah `product_snapshot` ke `meal_items`, memperbolehkan nilai gizi legacy kosong untuk produk kemasan, dan menambah tabel `user_products` dengan RLS berdasarkan `auth.uid()`. Produk dari label yang dipilih untuk disimpan hanya berada di tabel pemiliknya. Kode yang sama dapat dimiliki pengguna berbeda; kombinasi `(user_id, barcode)` mencegah duplikasi kode dalam satu akun. Catatan makan tetap memakai jalur `meals`/`meal_items` lama. Kolom `grams` legacy memegang jumlah numerik untuk produk kemasan; unit yang sesungguhnya dan dasar nilai gizi disimpan di `product_snapshot`, dan tampilan selalu memakai unit snapshot tersebut. Aplikasi akun memerlukan migrasi ini sebelum deploy MVP 7.

Uji kamera pada perangkat mobile, lookup langsung ke Open Food Facts, dan eksekusi uji SQL RLS membutuhkan lingkungan terhubung. Unit test memeriksa checksum barcode, pemetaan g/ml/sajian, nilai kosong, dan pengaruhnya pada ringkasan mingguan.
